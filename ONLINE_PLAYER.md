# orynq. online music

This checkout adds an anonymous YouTube Music experience to the existing native Kotlin/Compose player. It uses the community InnerTubeX 0.7.2 library; no official YouTube Data API developer key is required.

## Implemented

- Display branding is `orynq.` across launcher labels (including debug and Watch variants), localized UI, notifications, widgets, sharing, and project documentation. Home uses a plain rounded wordmark with streaming and Settings actions; the Beta pill and changelog action are removed. Existing package/data identifiers retain update compatibility.

- The original Home top bar is retained above one featured song card and a song list. The original docked Search bar, genre tiles, result rows, and Library remain. Home has no added marketing slogans or search field.
- Save/unsave tracks in a persistent online library. Saved metadata is not an offline audio download.
- Search calls YouTube Music's `WEB_REMIX` search with Metrolist's song-only filter, excludes video cards, and uses each card's own playback ID. Clear title/artist matches narrow unrelated recommendations while preserving server order; queries without metadata matches retain server results for typo/transliteration support. Local matches remain in the original results UI. Online category tiles submit searches. No file-icon switch remains.
- Playback prefers usable YouTube Music clients after the extractor's capability/token checks and requests `AudioQuality.HIGH`. It can fall back to another compatible client for the same music track. This does not imply lossless audio or Premium-only bitrate access.
- An anonymous WebView proof-token provider implements the InnerTubeX webpage-attestation protocol. Its runtime blocks network/navigation and file/content access; bounded trusted HTTP fetches stay in the adapter. Tokens and integrity state stay in memory and are excluded from logs. Account-cookie sessions are not supported by this adapter.
- Online favorites use the original heart controls and appear in the Library's Liked tab alongside local favorites.
- Known YouTube image CDN size transforms request 1200-pixel artwork. Both native image loaders upgrade URLs at display time, including old playback queues. Upgraded image requests use fresh cache keys. The full-player carousel requests 1200-pixel decoding for online tracks rather than its default 512-pixel medium setting.
- Standard YouTube video-thumbnail paths request `maxresdefault.jpg` without small-image sizing parameters; a missing maximum-size image falls back to `hqdefault.jpg`. Available source resolution still depends on the uploader.
- Play a result as a queue, or add a track next, through the existing Media3 service and dual player engine.
- Resolve stable `youtube://VIDEO_ID` references on the player's loader thread, preserving per-stream headers. In-memory URL caching observes expiry. Initial 401/403/410 responses invalidate the rejected URL, temporarily exclude its client/profile for that track, and allow two further client attempts; rejection state expires after five minutes.
- Progressive audio supports ordinary and bounded HTTP ranges, including byte-range seeks. Range responses are checked before passing bytes to the player.
- Home metadata is cached for browsing when a subsequent refresh fails. Signed URLs and credentials are not persisted with favorites or home metadata.
- Continue setup with online music without granting local media access. The existing local setup and library remain available.

## Boundaries

- This is an initial implementation, not a verified production YouTube client. Compilation, unit tests, device playback, and visual QA are separate checks.
- SABR and HLS are explicitly disabled in extraction. Tracks for which no supported progressive stream is available fail rather than handing an incompatible protocol to the player.
- Account login, personalized account feeds, album/playlist detail pages, continuation pagination, downloads, and cast transport for online tracks are not implemented.
- Mood chips submit searches; they do not claim account-personalized recommendations.
- Existing third-party service integrations are retained.
